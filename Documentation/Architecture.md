# Architecture

`ConnectionManager` is the main-actor coordinator and owns the lifetime of capture, connection and recovery. `StreamState` handles permission/stop races and interruption transitions. Permission completion, meter updates, route rebuilds and network callbacks carry generation tokens so an older session cannot restart a stopped microphone.

`PermissionManager` requests standard microphone permission only on an explicit Start. `BackgroundAudioManager` activates `AVAudioSession.playAndRecord` with measurement mode (default mode when Bluetooth is enabled), preferred rate and I/O duration. It observes interruption, route and media-service-reset notifications. It never creates a fake background task or playback loop.

`AudioCaptureManager` owns `AVAudioEngine.inputNode`. The tap admits at most three copied hardware buffers; conversion runs on a serial user-initiated queue. Borrowed tap storage is copied before the callback returns. Stop invalidates admission, removes the tap, stops the engine and drains admitted work before replacing callbacks. Buffer copies/allocations remain in the tap; this is bounded work, not a claim of a fully allocation-free real-time pipeline. Device profiling may justify a preallocated pool later.

`AudioFormatConverter` keeps one `AVAudioConverter` per hardware route. It resamples/downmixes to mono Float32 with a stateful converter and `.noDataNow` for temporary input exhaustion, then uses the portable `PCM16` encoder for saturating little-endian Int16. The input is supplied once per conversion call; it is not endlessly repeated. `PCMFramer` accumulates partial output and emits exact 10 ms packets. On discontinuity/route restart its remainder is discarded instead of sending stale partial audio.

`NetworkStreamingManager` owns an NWConnection on a serial network queue. The production connection requires Wi-Fi and prohibits cellular. Manual endpoint validation accepts RFC1918 or link-local IPv4 only. Connect sends unicast DISCOVER; Start switches to HELLO. AUDIO waits for an ACK, stops on BUSY or stale replies, and is never held until connectivity returns. At most 2/4/8 unsent packets and one in-flight audio datagram are retained. A single scheduled drain prevents an unbounded dispatch backlog. Queue overflow drops oldest audio and reports a counter. Send completion means local delivery to the network stack, not proven playback on the PC.

Mute sets the capture encoder to silence, clears queued network audio, and forces silence again at send time. An already submitted UDP datagram cannot be recalled. Stop drains capture, disables network admission, clears queued audio, stops HELLO, recreates an idle probe socket and deactivates AVAudioSession. Disconnect also cancels the socket and timers. Idle probe connections are dropped when the app leaves the foreground; active capture is not stopped by scene changes.

The app does not automatically start after launch, foregrounding, network reconnection or permission changes. After an already active recording is interrupted, restart is attempted only if iOS signals shouldResume and the session is still wanted. Route/media-service recovery has a cancellable 300 ms debounce. Failed restart stops capture and provides a visible explanation.

Settings persist in local UserDefaults only. No audio is recorded to disk. OSLog contains state/error events, not PCM. No third-party Swift dependencies are used. The test-only `requiresWiFi: false` initializer permits loopback UDP on a simulator; the production coordinator uses the Wi-Fi default.
